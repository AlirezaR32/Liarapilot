# 🛩️ LiaraPilot — ایجنت خودکار DevOps و SRE برای ابر لیارا

LiaraPilot یک دستیار **ایجنت‌محور** برای تیم‌هایی است که برنامه‌هایشان را روی [ابر لیارا](https://liara.ir) مستقر می‌کنند. این ابزار به GitHub وصل می‌شود، مخزن شما را تحلیل می‌کند، بر پایه‌ی شواهد (نه حدس) برنامه‌ی استقرار می‌سازد، عملیات تأییدشده را از طریق یکپارچه‌سازی‌های اعتبارسنجی‌شده اجرا می‌کند، و یک چرخه‌ی SRE کم‌هزینه برای پایش و رفع خرابی می‌چرخاند — و **قبل از هر کار مهم، از شما تأیید می‌گیرد**.

این پروژه عمداً یک «چت‌بات با داشبورد» نیست: تحلیل خودکار انجام می‌شود، چت اختیاری است، و هر پیشنهاد یک اکشن واقعی و قابل‌اجرا همراه دارد.

## چه چیزهایی واقعاً کار می‌کنند

| قابلیت | وضعیت |
|---|---|
| تحلیل مخزن → ساختار `ProjectProfile` با شواهد و ضریب اطمینان، کش بر اساس revision | ✅ کار می‌کند (GitHub/GitLab واقعی با توکن هر کاربر؛ مخازن عمومی بدون توکن) |
| پایپ‌لاین استقرار LangGraph با **چک‌پوینت ماندگار** (وسط تأیید، با ری‌استارت هم از دست نمی‌رود) | ✅ کار می‌کند (checkpointer سفارشی Prisma) |
| دروازه‌ی تأیید انسانی با `interrupt()` در LangGraph | ✅ کار می‌کند |
| **مرورگر مخزن‌ها** («مخازن من») — فهرست مخزن‌های خود کاربر از GitHub/GitLab با توکن خودش، جستجو و «اتصال و استقرار» یک‌کلیکی | ✅ کار می‌کند (`GET /api/repos`) |
| **استقرار از سورس واقعی مخزن کاربر** — دانلود tarball در همان revision، استخراج روی دیسک داده و `liara deploy --path <سورس>` | ✅ کار می‌کند (سقف ۳۰۰MB + پاک‌سازی خودکار) |
| **ساخت خودکار اپ لیارا** هنگام اولین استقرار تأییدشده (POST /v1/projects، ارزان‌ترین پلن از `liara plan list`، پلتفرم تشخیص‌داده‌شده) | ✅ کار می‌کند |
| **لاگ زنده بیلد** در کارت پیشرفت + **لینک نهایی** `https://<app>.liara.run` با دکمه کپی/باز کردن و healthUrl پیش‌فرض | ✅ کار می‌کند |
| اجرای استقرار با آداپتور CLI اعتبارسنجی‌شده — همیشه واقعی | ✅ کار می‌کند (با توکن API لیارای هر کاربر از «تنظیمات») |
| تأیید پس از استقرار (پروب واقعی HTTP + endpoint نسخه‌های لیارا) | ✅ کار می‌کند |
| بازیابی خرابی قطعی: دسته‌بندی خطاهای build و **امتناع از retry کورکورانه** | ✅ تست‌شده |
| پایش سبک HTTP (بدون LLM)، حذف تکرار رخدادها و cooldown | ✅ کار می‌کند |
| تحلیل رخداد با LLM بودجه‌دار → تشخیص ساختاریافته → پیشنهاد رفع با تأیید | ✅ کار می‌کند |
| انقضای تأیید، اتصال به hash پلن، اعتبارسنجی مجدد قبل از اجرا، رد کامل ممیزی | ✅ تست‌شده |
| چت متنی به پروژه، پیشرفت زنده‌ی SSE، وب‌هوک GitHub (HMAC + حذف تکرار) | ✅ کار می‌کند |
| **بدون نیاز به لاگین** — فضای کاری باز است؛ فقط سرویس‌ها را وصل می‌کنید | ✅ طراحی جدید |
| **رابط کاربری فارسی راست‌به‌چپ** (Vazirmatn، اعداد و تاریخ جلالی) + سوئیچ فارسی/English | ✅ کار می‌کند |
| **اتصال گیت‌هاب و گیت‌لب** — PAT با اعتبارسنجی زنده + OAuth یک‌کلیکی (اختیاری) | ✅ کار می‌کند (OAuth با تنظیم client id/secret فعال می‌شود؛ PAT همیشه در دسترس است) |
| **تحلیل مخازن GitLab** (gitlab.com و سلف-هاست) کنار گیت‌هاب | ✅ کار می‌کند |
| **اتصال هوش مصنوعی (ChatGPT/سازگار با OpenAI)** — کلید خودِ کاربر، از UI | ✅ کار می‌کند (تنظیمات ← هوش مصنوعی؛ بدون env) |

**هنوز نیست / خارج از دامنه به‌صورت عمدی:** استقرار از طریق آرشیو سورس (نیازمند UI آماده‌سازی آرشیو)، تحویل پچ از طریق PR. و زمان‌بند پایش درون‌پردازشی است — که روی لیارا (کانتینر همیشه‌روشن) به‌خوبی کار می‌کند؛ فقط نباید به بیش از یک نمونه scale شود.

## شروع سریع

```bash
bun install
cp .env.example .env          # فقط placeholder — برای حالت دمو هیچ کلیدی لازم نیست
bun run db:push               # ساخت دیتابیس SQLite
bun run dev                   # http://localhost:3000
bun run test                  # ۳۵ تست واحد + یکپارچه
bun run lint
```

بعد از باز کردن صفحه، دکمه‌ی **«Load demo workspace»** را بزنید. سه پروژه‌ی نمایشی (با برچسب واضح دمو) ساخته می‌شود:

1. **orders-api** — پایپ‌لاین استقرار را اجرا کنید؛ روی دروازه‌ی تأیید توقف می‌کند. از نمای **Approvals** تأیید کنید و پیشرفت زنده‌ی SSE تا اجرا و تأیید نهایی را ببینید.
2. **checkout-api** — اپ شبیه‌سازی‌شده خطای HTTP 500 برمی‌گرداند؛ مانیتور بدون LLM آن را تشخیص می‌دهد، شواهد جمع می‌شود، LLM تشخیص می‌دهد و درخواست تأیید رفع خرابی ثبت می‌شود.
3. **billing-api** — استقرار به‌صورت قطعی در مرحله‌ی build شکست می‌خورد و ایجنت **به‌جای retry کورکورانه متوقف می‌شود**.

هیچ مسیر mock در محصول وجود ندارد — اجرای استقرار همیشه واقعی است و پیش از هر عمل پیامدساز از دروازهٔ تأیید انسانی رد می‌شود.

## متغیرهای محیطی

**تقریباً هیچ!** — مدل تجاری: هر توکنی توسط کاربر داخل خود اپ وارد و رمزنگاری‌شده ذخیره می‌شود. برای دیپلوی چیزی لازم نیست:

| متغیر | الزام | توضیح |
|---|---|---|
| `DATABASE_URL` | خودکار | entrypoint به‌صورت پیش‌فرض `file:/app/data/liarapilot.db` (روی دیسک متصل) تزریق می‌کند |
| `LIARAPILOT_SECRET` | اختیاری | کلید رمزنگاری AES-256-GCM. اگر تنظیم نشود، در اولین اجرا یک کلید تصادفی ۲۵۶ بیتی **روی دیسک داده** ساخته و ذخیره می‌شود (بقا پس از ری‌استارت) |
| `PORT` | خودکار | پیش‌فرض ۳۰۰۰ (liara.json همان را اعلام می‌کند) |

> هیچ توکن GitHub/GitLab/Liara/OpenAI در env تعریف نمی‌شود — همه از «تنظیمات» داخل اپ، به‌ازای هر فضای کاری.
> ⚠️ طبق مستندات لیارا، تعریف `envs` در `liara.json` **تمام متغیرهای قبلی را پاک می‌کند**؛ اگر روزی متغیر خودتان را لازم داشتید، همیشه از `liara env set` استفاده کنید.

## استقرار روی لیارا — قدم به قدم

این پروژه برای اجرا روی لیارا به‌صورت **اپ Docker** بسته‌بندی شده است (فایل‌های `Dockerfile`، `liara.json` و `docker-entrypoint.sh` در ریشه‌ی مخزن آماده‌اند). دیتابیس SQLite روی **دیسک ماندگار** لیارا در `/app/data` قرار می‌گیرد تا با هر استقرار یا ری‌استارت از دست نرود.

### راه سریع — اسکریپت کمکی گرافیکی

به‌جای اجرای دستی مراحل، دو اسکریپت آماده داریم که همه‌چیز را با خروجی رنگی و گام‌به‌گام هدایت می‌کنند:

```bash
bash scripts/deploy.sh   # چک پیش‌نیازها → احراز هویت → ساخت اپ/دیسک → env → استقرار → تست سلامت
bash scripts/logs.sh     # نمایشگر لاگ رنگی (خطا=قرمز، هشدار=زرد) + حالت زنده با Ctrl+C
```

اسکریپت deploy خطاهای رایج را هم مدیریت می‌کند (باگ `Invalid count value: -1` در ساخت اپ، نبودن دیسک، ثبت `DATABASE_URL`) و در پایان endpoint سلامت را چک می‌کند.

### ۱) پیش‌نیازها

- Node.js ≥ 18 روی سیستم شما (برای CLI)
- یک حساب کاربری در [کنسول لیارا](https://console.liara.ir) با اعتبار کافی برای یک اپ + یک دیسک ۱ گیگابایتی
- توکن API: از کنسول لیارا → **تنظیمات ← API Token** بگیرید

### ۲) نصب و ورود به CLI

```bash
npm install -g @liara/cli

# ورود غیرتعاملی با توکن (مناسب ترمینال و CI):
liara login --api-token=APEXxxxxxxxxxxxxxxxx

# بررسی اینکه لاگین موفق بوده:
liara account list
```

### ۳) ساخت برنامه و دیسک

> اگر می‌خواهید نام دیگری بگذارید، `liarapilot` را در همه‌ی دستورات و همچنین فیلد `app` در `liara.json` تغییر دهید.

```bash
# ساخت اپ با پلتفرم docker (به‌جای g1 می‌توانید پلن دلخواه را با `liara plan list` ببینید)
liara app create -a liarapilot --platform docker

# دیسک ماندگار برای SQLite (۱ گیگ کافی است) — باید قبل از اولین deploy ساخته شود
liara disk create -a liarapilot -n liarapilot-data -s 1
```

فایل `liara.json` در ریشه‌ی پروژه همه‌ی تنظیمات را حمل می‌کند (خوانده‌شده به‌صورت خودکار توسط `liara deploy`):

```json
{
  "app": "liarapilot",
  "platform": "docker",
  "port": 3000,
  "disks": [{ "name": "liarapilot-data", "mountTo": "/app/data" }],
  "healthCheck": {
    "command": "CMD wget -q -O /dev/null http://localhost:3000/api/health || exit 1",
    "interval": 30, "timeout": 10, "retries": 3, "startPeriod": 30
  }
}
```

### ۴) اتصال سرویس‌ها — بعد از دیپلوی، داخل خود اپ (بدون env!)

**هیچ متغیر محیطی لازم نیست.** دیپلوی کنید، اپ را باز کنید و از صفحهٔ «تنظیمات» سرویس‌ها را وصل کنید — هر بازدیدکننده فضای کاری خصوصی خودش را دارد و توکن‌های «خودش» را وارد می‌کند:

| سرویس | روش اتصال | چه چیزی فعال می‌شود |
|---|---|---|
| **GitHub** | «ورود با مرورگر» (Device Flow — کد یک‌بارمصرف در `github.com/login/device`) یا PAT با دسترسی `repo` | تحلیل مخازن خصوصی، سقف نرخ ۵۰۰۰/ساعت |
| **GitLab** | همان ورود مرورگری روی نصب شما، یا PAT با دسترسی `read_api` | تحلیل مخازن GitLab |
| **لیارا** | توکن API از `console.liara.ir/panel/api-keys` (اعتبارسنجی زنده با `GET /v1/me`) | استقرار/ری‌استارت/مقیاس/لاگِ **واقعی** روی اپ‌های خودتان |
| **هوش مصنوعی** | هر کلید سازگار با OpenAI (OpenAI، Azure، OpenRouter، vLLM محلی…) + Base URL و Model | گفت‌وگو، تشخیص حادثه، گزارش‌های استقرار |

**فعال‌سازی «ورود با مرورگر» برای همه (یک‌بار، اختیاری):** در `github.com/settings/developers` یک OAuth App بسازید، گزینهٔ **Device Flow** را فعال کنید و Client ID را در «تنظیمات ← ثبت OAuth App (شناسه‌های کلاینت)» ذخیره کنید. برای GitLab هم Application ID را با دسترسی `read_api` + Device Authorization Grant وارد کنید. Client ID عمومی است و secret لازم ندارد — هیچ restart یا env‌ای در کار نیست.

> 🔐 توکن‌ها با AES-256-GCM رمزنگاری می‌شوند؛ کلید رمزنگاری در اولین اجرا خودکار روی دیسک داده ساخته می‌شود. هیچ توکنی در لاگ، state یا پاسخ API ظاهر نمی‌شود.

### ۵) دیپلوی

از ریشه‌ی پروژه:

```bash
liara deploy -a liarapilot -b iran -m "first deploy"
```

چه اتفاقی در این مرحله می‌افتد:

- CLI کد را آپلود می‌کند و ایمیج Docker را **روی زیرساخت لیارا** با `Dockerfile` پروژه می‌سازد (build چندمرحله‌ای با Bun + اجرا با Node 22 + نصب `@liara/cli` داخل ایمیج).
- کانتینر در `entrypoint` اول اسکیمای Prisma را روی فایل SQLiteِ دیسک اعمال می‌کند (`prisma db push` — idempotent)، بعد سرور standalone را روی پورت ۳۰۰۰ بالا می‌آورد.
- Health check لیارا هر ۳۰ ثانیه `/api/health` را چک می‌کند.
- بعد از اتمام build، دامنه‌ی پیش‌فرض برنامه (مشابه `liarapilot.ir.liara.run`) در خروجی CLI و پنل نمایش داده می‌شود.

### ۶) تست پس از استقرار

```bash
# ۱) سلامت سرویس و دیتابیس:
curl https://YOUR-APP-DOMAIN/api/health
# {"status":"ok","db":"ok","latencyMs":2,...}

# ۲) رجیستری قابلیت‌های لیارا (خوانده‌شده از مستندات رسمی):
curl https://YOUR-APP-DOMAIN/api/capabilities | head -c 300

# ۳) لاگ زنده‌ی برنامه (برای دیدن boot موتور و کوئری‌های زمان‌بند):
liara app logs -a liarapilot -f
```

سپس سناریوی کامل را از خود UI تست کنید:

1. دامنه‌ی برنامه را در مرورگر باز کنید → مستقیم داخل **فضای کاری خصوصی خودتان** می‌روید (بدون صفحه‌ی ورود؛ رابط فارسی و راست‌به‌چپ).
2. در «تنظیمات» گیت‌هاب را وصل کنید (مرورگری یا PAT) و سپس توکن API لیارا را وارد کنید.
3. یک مخزن وصل کنید → تحلیل خودکار اجرا می‌شود و برنامهٔ استقرار فارسی ساخته می‌شود.
4. **درخواست استقرار** بزنید → به **تأییدیه‌ها** بروید و تأیید کنید → پیشرفت زندهٔ گردش‌کار تا استقرار و راستی‌آزمایی را ببینید.
5. در «گفت‌وگو» سؤال بپرسید — پاسخ بر اساس شواهد واقعی فضای کاری است.
5. به **Settings** بروید و اتصال‌ها را چک کنید (بخش بعدی راهنمای کامل است).

> بعد از اتصال توکن API لیارا در «تنظیمات»، همان UI می‌تواند اپ‌های **واقعیِ** حساب لیارای شما را لیست و مدیریت کند (همچنان پشت دروازه‌ی تأیید و با whitelist فرمان). بدون اتصال، درخواست استقرار با پیام راهنما متوقف می‌شود.

### ۷) وب‌هوک گیت‌هاب (اختیاری)

در مخزن گیت‌هاب: **Settings → Webhooks → Add webhook**

- URL: `https://YOUR-APP-DOMAIN/api/webhooks/github`
- Content type: `application/json`
- Secret: یک رشتهٔ تصادفی — و همان را با `liara env set -a <APP> GITHUB_WEBHOOK_SECRET=...` روی اپ ثبت کنید (تنها متغیر اختیاری؛ بدون آن، webhook غیرفعال می‌ماند و بقیهٔ برنامه مستقل کار می‌کند)

روی push، مخزن دوباره تحلیل می‌شود (هیچ استقراری خودکار انجام نمی‌شود — همیشه از مسیر تأیید می‌گذرد).

## اتصال گیت‌هاب/گیت‌لب، ChatGPT و زبان فارسی

### ۱) بدون لاگین — فقط اتصال (Connect)

طبق طراحی جدید، **ورود/ثبت‌نام حذف شده است**. فضای کاری از همان اولین بازدید باز است و چیزی برای به‌خاطر سپردن نیست. چیزی که وصل می‌کنید سرویس‌هاست، نه حساب کاربری:

- **GitHub / GitLab** → توکن خود را در Settings وصل کنید تا مخزن‌های خصوصی‌تان تحلیل شوند.
- **ChatGPT** → کلید OpenAI را روی سرور تنظیم کنید تا مغز ایجنت شود (بخش ۴).
- **لیارا** → توکن API را در «تنظیمات ← اتصال لیارا» وارد کنید تا عملیات واقعی (deploy/restart/logs) اجرا شود.
- OAuth یک‌کلیکی هم بدون لاگین کار می‌کند: دکمه‌ی Connect، هویت گیت‌هاب/گیت‌لب را به همین فضای کاری متصل می‌کند.
- توکن‌ها بعد از اعتبارسنجی با AES-256-GCM رمزنگاری و ذخیره می‌شوند و هرگز دوباره نمایش داده نمی‌شوند.

> اگر برنامه را روی اینترنت عمومی مستقر می‌کنید و برایتان مهم است که غریبه‌ها workspace شما را نبینند، اپ را روی دامنه‌ی خصوصی نگه دارید یا یک لایه‌ی احراز هویت (مثل Basic Auth در Caddy/پنل لیارا) جلوی آن بگذارید.

### ۲) زبان فارسی و راست‌به‌چپ (RTL)

کل رابط کاربری به‌صورت پیش‌فرض **فارسی و راست‌به‌چپ** است:

- فونت **Vazirmatn** (داخل ایمیج self-host شده — بدون درخواست خارجی)، چینش آینه‌ای کامل (flex/grid، فاصله‌ها و آیکن‌ها با ویژگی‌های منطقی `ms-/me-/ps-/pe-`).
- اعداد در متن فارسی با ارقام فارسی و تاریخ‌ها با **تقویم جلالی** نمایش داده می‌شوند؛ مقادیر فنی (کامیت SHA، کد HTTP، مدت‌زمان) لاتین می‌مانند تا خوانایی فنی حفظ شود.
- دکمه‌ی **«فارسی / English»** در هدر زبان را عوض می‌کند؛ انتخاب در `localStorage` ذخیره می‌شود و جهت صفحه (rtl/ltr) هم خودکار سوییچ می‌شود.

### ۳) اتصال گیت‌هاب — دو روش

**روش A (پیشنهادی): ورود با مرورگر — OAuth Device Flow**

1. مالک نصب (یک‌بار): در `github.com/settings/developers` → **New OAuth App** (هر Homepage/Callback) → بعد از ساخت، گزینه‌ی **Enable Device Flow** را فعال کنید → Client ID را کپی کنید.
2. در LiaraPilot: **تنظیمات ← ثبت OAuth App (شناسه‌های کلاینت)** → Client ID را ذخیره کنید (بدون restart، بدون env).
3. هر کاربر: **تنظیمات ← GitHub ← «ورود با مرورگر»** → کد ۸ رقمی نمایش داده می‌شود → در مرورگر خودتان `github.com/login/device` را باز کنید، کد را وارد و تأیید کنید → همین پنجره خودکار متصل می‌شود.
4. توکن مستقیماً از GitHub تحویل گرفته، اعتبارسنجی و رمزنگاری‌شده ذخیره می‌شود؛ هویت شما (`@username`) با بِج «متصل · از طریق oauth» نمایش داده می‌شود.

**روش B: توکن شخصی (PAT) — بدون هیچ تنظیمی همین حالا کار می‌کند**

1. در گیت‌هاب: Settings → Developer settings → Personal access tokens → Generate new token
2. اسکوپ‌های لازم برای مخازن خصوصی: `repo` (برای عمومی فقط `read:user` کافی است)
3. در LiaraPilot: **تنظیمات ← GitHub** → توکن را paste کنید → **اتصال با توکن**
4. توکن بلافاصله با `api.github.com/user` اعتبارسنجی و به‌صورت رمزنگاری‌شده (AES-256-GCM) ذخیره می‌شود؛ دیگر نشان داده نمی‌شود.

> مخازن **عمومی** حتی بدون هیچ اتصالی تحلیل می‌شوند (با سقف نرخ ۶۰/ساعت). با اتصال حساب خودتان، سقف به ۵۰۰۰/ساعت و مخازن خصوصی باز می‌شود.

### ۳) اتصال گیت‌لب — دو روش

**روش A: PAT (بدون تنظیم، همین حالا):**

1. در گیت‌لب: Preferences → Access Tokens → توکن با اسکوپ `read_api` (یا `api`) بسازید.
2. در LiaraPilot: **Settings → GitLab** → آدرس اپونس (پیش‌فرض `https://gitlab.com`، برای سلف-هاست آدرس خودتان) + توکن → **Connect**.

**روش B (پیشنهادی): ورود با مرورگر — Device Flow**

1. مالک نصب (یک‌بار): در گیت‌لب: User Settings → Applications → اپ جدید با اسکوپ `read_api` و تیک **Device Authorization Grant** → Application ID را کپی کنید (secret فقط برای اپ‌های محرمانه).
2. در LiaraPilot: **تنظیمات ← ثبت OAuth App** → Application ID و آدرس اپونس (برای سلف-هاست آدرس خودتان) را ذخیره کنید.
3. هر کاربر: **تنظیمات ← GitLab ← «ورود با مرورگر»** → کد را در `{instance}/oauth/device` وارد کنید.

بعد از اتصال، هنگام افزودن پروژه‌ی جدید می‌توانید **تب GitLab** را انتخاب کنید (فرم «Connect a repository») تا مخزن گیت‌لب با همان تحلیل هدفمند (metadata، commit، فایل‌های کلیدی) بررسی شود.

### ۴) اتصال هوش مصنوعی (ChatGPT / سازگار با OpenAI) — از داخل اپ

مغز ایجنت پشت یک adapter است؛ کلیدش را **هر کاربر از UI** وارد می‌کند (بدون env، بدون restart):

1. در LiaraPilot: **تنظیمات ← هوش مصنوعی (ChatGPT / سازگار با OpenAI)**
2. کلید API (`sk-…`) + آدرس پایه (پیش‌فرض `https://api.openai.com/v1`) + مدل (پیش‌فرض `gpt-4o-mini`) را وارد کنید.
3. **«ذخیره و آزمایش»** بزنید — یک تماس آزمایشی واقعی با endpoint شما زده می‌شود؛ اگر ناموفق باشد خطای دقیق را می‌بینید.
4. بِج هدر به **ChatGPT (مدل شما)** تغییر می‌کند.

هر سرویس سازگار با OpenAI کار می‌کند: Azure OpenAI، OpenRouter، Together، vLLM محلی و… (کافی است Base URL را عوض کنید).

**LLM دقیقاً کجا برای تصمیم‌گیری استفاده می‌شود؟**

| نقطه‌ی تصمیم | ورودی LLM | خروجی LLM |
|---|---|---|
| **تشخیص حادثه (Diagnosis)** | بسته‌ی شواهد محدود و پاک‌سازی‌شده (بررسی‌های سلامت، لاگ‌های اخیر، استقرارهای اخیر) | علت‌های محتمل با ضریب اطمینان، اثر، ابهام و پیشنهاد کوچک‌ترین اقدام بازگشت‌پذیر |
| **گزارش پایپ‌لاین استقرار** | پروفایل پروژه + نتیجه‌ی گام‌ها | تیتر، توضیح و گام‌های بعدی قابل‌فهم برای انسان |
| **چت زمینه‌ای** | سوال شما + شواهد همان پروژه از دیتابیس | پاسخ مبتنی بر شواهد — LLM به هیچ ابزار اجرایی دسترسی ندارد |

نکته‌ی مهم معماری: **جمع‌آوری شواهد و اجرای عملیات هرگز با LLM نیست** — کد قطعی (deterministic) است. LLM فقط روی شواهدِ آماده «استدلال» می‌کند و هر پیشنهاد اجرایی باید از دروازه‌ی تأیید انسانی رد شود. اگر OpenAI در دسترس نباشد، همان درخواست خودکار با مدل داخلی z-ai پاسخ داده می‌شود — ایجنت هرگز از کار نمی‌افتد و کاربر پیام خطای خام نمی‌بیند. مصرف هر تماس (token in/out) در صفحه‌ی Activity ثبت می‌شود.

### ۵) چک‌لیست تست نسخه‌ی نهایی

بعد از deploy روی لیارا، این ۸ مرحله را به ترتیب بزنید — کل مسیر حدود ۵ دقیقه است:

| # | تست | نتیجه‌ی مورد انتظار |
|---|---|---|
| ۱ | باز کردن `https://YOUR-APP-DOMAIN/api/health` | `{"status":"ok","db":"ok",...}` |
| ۲ | باز کردن دامنه در مرورگر | فضای کاری خصوصی خودتان — بدون صفحه‌ی ورود؛ UI فارسی و راست‌به‌چپ |
| ۳ | دکمه‌ی «فارسی / English» در هدر | زبان و جهت صفحه (rtl/ltr) سوییچ می‌شود و انتخاب می‌ماند |
| ۴ | تنظیمات ← GitHub ← «ورود با مرورگر» (یا PAT) | کد یک‌بارمصرف → تأیید در github.com/login/device → بِج «متصل · از طریق oauth» + `@username` |
| ۵ | تنظیمات ← لیارا ← توکن API از کنسول | اعتبارسنجی زنده با `api.liara.ir` → «لیارا وصل شد به‌عنوان {ایمیل}» |
| ۶ | Overview → اتصال یک مخزن (تب GitHub یا GitLab) | تحلیل خودکار + پروفایل زبان/فریمورک/دستور start |
| ۷ | درخواست استقرار → تأییدیه‌ها → تأیید | پیشرفت زنده تا استقرار **واقعی روی اپ لیارای شما** + گزارش راستگویانه با راستی‌آزمایی HTTP |
| ۸ | تنظیمات ← هوش مصنوعی ← کلید OpenAI | آزمایش موفق → بِج ChatGPT → گفت‌وگو و تشخیص حادثه با مدل خودتان |

## عیب‌یابی

| مشکل | علت رایج / راه‌حل |
|---|---|
| `Cannot find module 'effect'` در لاگ کانتینر (نسخه‌های قدیمی‌تر ایمیج) | باگ کپی ناقص Prisma CLI در Dockerfile — با آخرین نسخه‌ی مخزن رفع شده (CLI با کل وابستگی‌هایش در `/opt/prisma-cli` نصب می‌شود). اگر باز دیدید: آخرین کد را pull و دوباره deploy بدهید |
| `The table main.Job does not exist` بعد از بوت | نتیجه‌ی خطای بالا: `db push` اجرا نشده و جدول‌ها ساخته نشده‌اند. با ایمیج جدید، بار اول بوت خودش اسکیما را می‌سازد |
| `Invalid count value: -1` هنگام `liara app create` | باگ شناخته‌شده‌ی CLI نسخه ۹.۶ — نادیده بگیرید: `liara deploy` خودش اپ را می‌سازد، یا اپ را از پنل با پلتفرم Docker بسازید |
| `Error: CODE 400: Disk ... does not exist` هنگام deploy | دیسک باید **قبل از اولین deploy** ساخته شده باشد: `liara disk create -a liarapilot -n liarapilot-data -s 1` یا از پنل |
| build وسط کار می‌ایستد / `Killed` / خطای حافظه | پلن اپ برای `next build` کوچک است — از پنل موقتاً پلن بزرگ‌تر (مثلاً g2) انتخاب کنید و دوباره deploy بدهید |
| `/api/health` مقدار `degraded` برمی‌گرداند | دیسک متصل نیست یا قابل نوشتن نیست. تطبیق `mountTo` (در `liara.json`) با `DATABASE_URL` را چک کنید |
| کانتینر مدام ری‌استارت می‌شود | معمولاً health check fail می‌شود؛ `liara app logs -a liarapilot` را ببینید. `startPeriod: 30` برای شروع کافی است |
| خطای build در `bun install` | `bun.lock` باید در مخزن commit شده باشد؛ نسخه‌ی lockfile و `package.json` هماهنگ باشند |
| استقرار با خطای «اتصال لیارا برقرار نیست» متوقف می‌شود | توکن API لیارا در «تنظیمات ← اتصال لیارا» وصل نشده؛ توکن را از کنسول لیارا بگیرید و وصل کنید |
| دامنه باز نمی‌شود | اپ ممکن است خاموش (stopped) باشد: `liara app start -a liarapilot` |
| متغیرهای محیطی ناگهان پاک شدند | `envs` در `liara.json` تعریف کرده‌اید — طبق مستندات لیارا این کار همه‌ی متغیرهای قبلی را حذف می‌کند |
| خطای «app not found» هنگام deploy | `-a liarapilot` با شناسه‌ی اپ ساخته‌شده یکی باشد؛ یا اپ را بسازید (`liara app create`) |

## مدل امنیتی

- **قطعی بر LLM**: مسیریابی، ورودی‌های پلن، دسته‌بندی خرابی و پایش همگی کد معمولی‌اند. LLM فقط برای تشخیص رخداد و چت، و آن هم با بودجه، صدا زده می‌شود.
- **تأیید = مرز سیاستی**: عملیات پرنتیج (استقرار، ری‌استارت، تغییر env، rollback، نوشتن در مخزن) به تأییدی نیاز دارند که به hash همان پلن قفل شده، ۳۰ دقیقه اعتبار دارد و **درست قبل از اجرا دوباره اعتبارسنجی می‌شود**.
- **قابلیت ساختگی وجود ندارد**: هر عملیات لیارا با رجیستری وضعیت تأیید (`docs/api-capabilities.md`) چک می‌شود؛ مورد تأییدنشده ⇒ ایجنت امتناع می‌کند و توضیح می‌دهد.
- **سِکرت‌ها**: فقط reference در state/پرامپت/لاگ سفر می‌کند؛ redaction قبل از هر ورودی مدل یا ذخیره‌سازی؛ مقدار env هرگز از مخزن خوانده نمی‌شود.
- **بدون shell دلخواه**: آداپتور CLI فقط قالب‌های فرمان whitelist‌شده را با اعتبارسنجی سخت‌گیرانه، timeout و سقف خروجی اجرا می‌کند. خروجی LLM هرگز نمی‌تواند به فرمان تبدیل شود.

جزئیات کامل: `docs/security.md` و `docs/operations.md`.

## معماری در یک نگاه

```
یک اپ Next.js 16 با جداسازی لایه‌ای:
src/lib/agent/        گراف‌های LangGraph (پایپ‌لاین استقرار، تحلیل رخداد)، موتور سیاست
src/lib/integrations/ گیت‌هاب (+fixture) · رجیستری قابلیت / API / آداپتور CLI لیارا · آداپتور LLM
src/lib/services/     پروژه‌ها، استقرارها، رخدادها، تأییدها، ممیزی، پایش
src/lib/workers/      صف کار مبتنی بر DB، زمان‌بند، runner ورک‌فلو (موتور درون‌پردازشی)
src/lib/persistence/  checkpointer مبتنی بر Prisma برای LangGraph (interrupt ماندگار)
src/lib/security/     redaction، اعتبارسنجی فرمان، credential ref، scope نشست
src/app/api/          REST تایپ‌شده (+ SSE، وب‌هوک، هدف دمو، /api/health)
src/components/liarapilot/  فضای کاری تک‌صفحه‌ای
```

داده روی SQLite (فایل روی دیسک لیارا) نگه داشته می‌شود و اسکیمای Prisma برای مهاجرت بعدی به PostgreSQL طراحی شده است.
